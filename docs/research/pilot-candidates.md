# 파일럿 후보 조사 — 공개 자료만 사용

확인일: **2026-11-02 UTC**. 조사 후보 5개 프로젝트, 초대 발송 0건,
응답 0건, 완료한 외부 파일럿 0건, 확인된 유용한 사례 0건이다.

아래는 인터뷰 후보 목록이다. 프로젝트를 유지관리한다는 사실이나 공개 이슈가
있다는 사실은 SkillWhy를 원하거나 참여에 동의했다는 증거가 아니다. 개인의 OS,
Codex 버전, 현재 문제, 연락 선호, 응답 가능성은 추정하지 않았다. 이슈에 적힌
환경도 **당시 제보자의 관찰**이며 프로젝트 유지관리자의 현재 환경이 아니다.

활동 날짜는 조사 시 GitHub API에서 확인한 **기본 브랜치의 최신 커밋 날짜**다.
모든 브랜치·토론·개인의 최신 활동을 뜻하지 않는다. 봇 커밋도 프로젝트 활동일
뿐 사람의 참여 의사로 해석하지 않는다. 개인 이메일은 수집하지 않았다.

### C01 — EJRyan89 / coding-agent-skills

- **관찰:** [Codex 지원 문서](https://github.com/EJRyan89/coding-agent-skills/blob/main/docs/codex-support.md)는 이미 `codex app-server`의 `skills/list`로 발견 여부를 검증하며, 같은 이름의 복수 항목·파싱 오류·비활성 항목을 구분한다. 별도 모델 카탈로그 확인도 설명한다. SkillWhy가 이 접근을 처음 만들었다고 주장하면 안 된다.
- **활동 근거:** [기본 브랜치 커밋](https://github.com/EJRyan89/coding-agent-skills/commit/37ffe59467e82402737e5b651d776a3df00af892), 2026-11-02 13:13 UTC. 제목은 Bash guard 수정이다. 관련 지원 문서의 [최근 변경](https://github.com/EJRyan89/coding-agent-skills/commit/865052c9db852a4c6b62df4eba0ba96ee15b3a4a)은 2026-10-25이며 Codex 설정 안내를 다룬다.
- **관련성 추론:** 기존 검증 도구와 별개로, 두 사람의 관찰을 작은 공유 파일로 비교하는 흐름이 도움이 되는지 비판적인 피드백을 받을 후보다. 기존 도구의 대체 필요성은 확인되지 않았다.
- **먼저 확인할 점:** 실제 지원 과정에서 비교 가능한 정보가 부족했던 최근 사례가 있는지. 현재 지원 조합에 해당하지 않으면 인터뷰와 합성 데모만 요청한다.

- **활동 근거:** [v7.0.1 커밋](https://github.com/obra/superpowers/commit/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b), 2026-10-21 21:00 UTC.
- **관련성 추론:** skill 패키지 지원 담당자가 설치 상태와 발견 상태를 구분하는 데 어떤 정보를 요구하는지 알아볼 후보다. 해당 Desktop 문제를 SkillWhy가 진단하거나 고쳤다는 뜻은 아니다.
- **먼저 확인할 점:** fresh CLI 관찰만으로도 유용한 지원 상황이 있는지. 닫힌 이슈를 재개하거나 제품 초대를 댓글로 붙이는 대상으로 사용하지 않는다.

### C03 — vercel-labs / skills

- **관찰:** [이슈 #810](https://github.com/vercel-labs/skills/issues/810)은 특정 agent에서 제거한 뒤에도 공유 경로 때문에 Codex가 skill을 발견한다는 제보다. 2026-03-31 작성, 2026-07-17 갱신, 조사 시 **open**이었다. 제보자의 원인 설명은 해당 환경의 보고이며 여기서 독립 재현하지 않았다.
- **활동 근거:** [설치 복원 관련 수정 커밋](https://github.com/vercel-labs/skills/commit/92a9a34ac3bf88e695e468b90c7bf32f163d32c8), 2026-10-29 00:49 UTC. 이 날짜는 프로젝트의 커밋 기록이며 특정 유지관리자의 피드백 가능성을 뜻하지 않는다.
- **관련성 추론:** 설치·제거 작업 전후의 native 발견 결과를 분리해 기록하는 방식에 대해 installer 유지관리 관점의 피드백을 받을 후보다. SkillWhy는 설치·삭제 도구가 아니며 이 이슈의 해결책이라고 소개하지 않는다.
- **먼저 확인할 점:** 현재도 비슷한 지원 문의가 있는지, 현행 도구의 출력으로 충분한지. 오래된 이슈를 현재 수요로 집계하지 않는다.
